# 4단계 실제 움직임 측정과 재보정

작성일: 2026-09-27

이 문서는 1.2 경로의 측정과 보정 실험 기록이다. 2026-09-28의 후속 진단과 1.3 후보 판정은 [SEQUENCE_GAP_FINDINGS.md](SEQUENCE_GAP_FINDINGS.md)를 참고한다.

## 결과와 채택 판단

실제 train의 구간 측정, 명령/관측 후보 변경, train 그룹 CV, 설정 고정 후 validation 비교를 실행했다.
추가로 정수 밀리초 타임스탬프의 FPS 추정 오류를 발견해 실제·합성 공통 전처리에서 수정했다.
**현재 보정 후보가 전체적으로 더 현실적인 궤적을 생성한다는 근거는 확보하지 못했다. 대량 생성 채택은 보류한다.**

| 단계 | 구현과 실행 결과 | 목표 달성 |
|---|---|---|
| 4-1 | 공통 2초·30Hz·4채널 입력, FPS clock 회귀 테스트 및 재처리 | 완료 |
| 4-2 | 기준 자료 비교와 실제 train의 행동 구간·시간 잔차 측정 | 완료 |
| 4-3 | train 근거로 행동 prior 조정, 관측 후보 6개와 그룹 CV | 보정 실험 완료; 개선 설정 확정은 미달성 |
| 4-4 | 후보를 고정한 뒤 별도 validation 그룹으로 평가 | 평가 완료; 개선 입증은 미달성 |

## 측정 방법

`motion_diagnostics.py`가 원본의 관측 가능한 구간을 30Hz로 변환한다. 0.1초 초과 누락을 넘어서 궤적을 연결하지 않는다.
0.3초의 Savitzky-Golay 추세와 국소 평균 이동으로 방향을 구하고, 추세를 뺀 잔차를 별도로 분석한다.
실제 train 33개 궤적, bird 16/drone 13개 잠정 원본 그룹을 읽었다.
full track 분석은 2초 창의 train 그룹당 8개 상한과 달리 전체 관측 가능한 구간을 사용한다.

| 측정 | 기준 | 결과 해석 |
|---|---|---|
| 저이동 | 속도가 max(화면 너비의 0.0015/초, 2×잔차 sigma/0.3초) 이하로 0.3초 유지 | 화면상의 저이동; 실제 공중 정지의 확정 아님 |
| 반전 | 전후 0.3초 평균 이동 방향이 135도 이상 다르고 양쪽에 이동 지지 | 평균 방향 전환; 실제 조이스틱 명령의 정답 아님 |
| 선회 | 같은 방향으로 20도/초 이상의 방향 변화가 0.3초 이상 지속하고 누적 30도 이상 | 화면상 연속 선회; 3D 회전 반경의 복원 아님 |
| 잔차 | 원래 위치에서 완만한 추세를 뺀 값의 robust sigma, ACF, PSD | 실제 운동·추적 오차·CMC 잔차가 혼합됨 |

짧은 누락의 보간 영향을 받는 주변과 구간 양끝은 방향 판정에서 제외한다.
분석 경계에서 잘린 이벤트는 left/right_censored로 표시한다. 여러 이벤트 종류가 같은 시간에 겹칠 수 있다.
이동 폭이 잔차와 비슷한 경우 unresolved로 남기며 물리적 호버로 확정하지 않는다.
이벤트가 검출되지 않았다는 사실도 그런 행동이 현실에서 없다는 뜻은 아니다.

원본 그룹의 총가중치는 같게 하고, 같은 그룹의 여러 분석 구간은 지속시간으로 가중한다.
방향/추세 폭을 0.2/0.3/0.45초, 반전각을 120/135/150도로 바꿔 민감도를 기록했다.

| 기본 설정 | bird | drone |
|---|---:|---:|
| 화면상 저이동 비율 | 2.68% | 6.50% |
| 화면상 반전 후보/분 | 0.00 | 0.97 |
| 연속 선회 후보/분 | 1.49 | 10.69 |
| 잔차 sigma 중앙값, 1920 너비 환산 px | 0.843 | 0.395 |

민감도 설정에서 drone 반전은 약 0.84~1.23회/분, 저이동은 약 6.25~6.92%였다.
bird 선회는 약 0.73~1.49회/분으로 기준 영향이 더 컸다. 잔차 크기도 추세 폭에 따라 달라져 순수 잡음 크기로 확정할 수 없다.

## 생성기 변경

물리 운동은 기존 v4 힘 모델을 유지한다. 새 생성 경로는 `sequence-guidance-1.2.0`이다.
`GuidanceProfile`로 명령 템플릿 확률과 지속시간을 명시적으로 저장하고, 실제 train 측정값을 참고하는 제한된 제안을 만든다.
화면상 빈도를 실제 3D 조종 빈도로 직접 동일시하지 않는다. 확률 하한/상한과 단일 모드 유지 비율은 설계 prior다.

- drone: 기존 반전 포함 템플릿 40%를 약 12%로 낮추고, 호버 템플릿 15%를 약 6.5%로 낮춘 제안이다. 명령 지속시간은 약 1.88~3.75초다.
- bird: 연속 추진을 약 52%로 늘리고, 전환형을 약 18%로 낮춘 제안이다. 명령 지속시간은 3~6초다.
- 순수 호버 템플릿은 정지 상태에서 시작하며 기존 힘 적분을 거친다. 전환 중의 감속/위치 유지는 즉시 멈추게 하지 않는다.
- 카메라는 두 클래스에 동일한 표본화 규칙을 사용한다. train 처리 종횡비를 참고해 공통 4:3 촬영 확률을 추가했다.
- 잡음은 기존 AR1, 독립 Gaussian, pooled 잔차 ACF 기반 AR2를 비교했다. AR2는 안정성 조건과 정상상태 분산을 검사한다.
- 잡음 계수에는 클래스별 값을 넣지 않는다. bird 전용 sine 신호를 중심 좌표에 추가하지 않는다.
- fixed-wing은 이번 비교 범위에 포함하지 않으며 기존 구현을 삭제하지 않았다.

선택된 후보는 기존 AR1 방식이다. AR2는 구현과 검증은 마쳤지만 CV에서 더 좋지 않아 선택하지 않았다.

## Clock 오류 수정

이전 전처리는 프레임 간 시간 차이의 중앙값으로 주기를 구했다.
30Hz를 정수 ms로 기록하면 33/34ms가 번갈아 나오므로 33ms를 주기로 추정해 30.303Hz로 오인했다.
그 결과 원래 약 30Hz인 자료에도 30.3Hz 초과 조건이 적용되어 저역통과 필터가 불필요하게 실행됐다.

전체 timestamp/frame_index clock의 기울기로 주기를 추정하도록 수정했다. 30/29.97/60/59.94Hz 반올림 시계와 짧은 dropout을 회귀 테스트했다.
계약은 `trajectory-sequence-1.0.1`, 기본 설정 ID는 `eb9be8154ee0f404`다. 모양 `(N,4,60)`과 공간 정규화 식은 유지한다.

이 수정이 모든 미세한 패턴 차이의 원인이라는 뜻은 아니다. 수정된 전처리에서도 보정 후보는 통과하지 못했다.
구 계약의 결과와 새 계약의 결과를 직접 성능 개선으로 비교하지 않는다. 새 비교에서는 기준 자료도 같은 전처리로 재처리했다.

## 누수 방지와 CV

1. 기존 원본 그룹의 train/validation 배치를 그대로 유지한다. 실제 test 좌표와 test.npz는 읽지 않는다.
2. 시간 주기 수정은 고정된 label-free 변환이다. validation 배열을 준비하는 데 좌표를 읽었지만 후보/보정값 선택에는 사용하지 않았다.
3. train에서 StratifiedGroupKFold 3-fold로 source group을 분리한다. 각 fold의 통계·카메라 기준·행동 prior는 fold-fit 그룹만으로 계산한다.
4. 각 fold의 held-out train 그룹과 합성을 비교한다. 후보 선택 점수는 클래스·지표 범주 동등 가중 거리 + 2×합성 비행 제외율이다.
5. 후보 가족을 선택하고 full train에서 설정을 다시 계산해 selected_profile.json과 SHA-256을 고정한다.
6. 별도 합성 seed와 실제 validation NPZ로 평가한다. 이후 후보를 다시 선택하지 않는다.

CV에는 클래스당 18개 합성 비행/fold, 마지막 생성 확인은 클래스당 18개, validation 비교는 클래스당 24개를 생성했다.
보정 전 기준 자료는 이전 v4 생성기의 저장 궤적을 재처리한 것이다. 보정 후 비행과 같은 물리 궤적의 짝 비교가 아니다.
validation은 이미 개발 과정에 반복 노출된 자료이며 촬영 세션 독립성도 잠정 상태다. 미사용 최종 평가로 보고하지 않는다.

동일한 수정된 입력 계약에서 계산한 결과이며 분류 정확도가 아니다. 거리는 낮을수록 좋다.

채택 검토는 공학적 보수적 기준이며 현실 동등성의 통계 검정이 아니다.

| 경로 | 용도 |
|---|---|
| output/train_motion_clock_v1_1 | 실제 train 33개 궤적의 이벤트 CSV, 통계, 민감도, 원본별 PNG |

위 sim_to_real_v3/v4는 실행 결과 폴더 이름이다. Feature v3/v4나 새로운 물리 모델 버전으로 해석하지 않는다.
output은 기존대로 gitignore 대상이다. 구현·테스트·이 명세는 Git 추적 대상이다.

```powershell
.\venv\Scripts\python.exe -m research.measure_train_motion --output research/output/train_motion_new_run
.\venv\Scripts\python.exe -m research.reprocess_development_sequences --output research/output/real_clock_new_run --reference-output research/output/clock_reference_new_run
```

각 명령은 새 출력 폴더에 실행한다. 기존 산출물을 덮어쓰지 않는다.
신규 입력을 추가하면 이전 manifest/group 배치가 그대로 유효하다고 가정하지 말고 원본 그룹부터 검토한다.

## 현재 결정과 C 전달 사항

현재 후보의 상태는 `not_ready_for_bulk_generation`이다. 기존 생성기를 자동 교체하지 않는다.
기존 생성기의 실제 현실성을 승인한 것도 아니다. 진단용 합성 NPZ를 C 최종 학습 데이터셋으로 배포하지 않는다.

이제 실제 움직임 측정과 반복 가능한 보정/평가 절차는 갖췄다. 그러나 현재 모델 계열과 후보 범위에서 유사도 개선에 성공했다고 말할 수 없다.
이 결과를 보고 C와 실제 기반 학습/소량 합성 추가 효과를 판단해야 한다. 실제 anchor를 활용하는 혼합 증강은 별도 다음 작업이다.

C에는 전처리 계약 1.0.1을 공유한다. 배열 형태가 같더라도 구 계약 데이터와 섞지 않으며, 최종 배포의 test도 동일 계약으로 별도 변환해야 한다.
이번 작업에서 C 모델을 학습하거나 대량 증강 데이터셋을 생성하지 않았다.

첫 명령은 177개 통과(323.86초), 보고서 판정 일치 회귀 테스트를 추가한 뒤 두 번째 명령은 8개 통과(77.12초)했다.
두 명령에 중복된 6개를 제외하면 서로 다른 테스트 179개를 확인했다.
노트북 실행도 통과했다. 테스트 통과는 구현의 확인이며 Sim-to-Real 개선의 증거를 대신하지 않는다.

별도 산출물 검사에서 실제 train `(156,4,60)`/validation `(59,4,60)`, 합성 fit `(196,4,60)`/evaluation `(270,4,60)`을 확인했다.
유한 float32, 좌표-변위 채널 일치, 실제 행/label/group 정렬, 실제/합성 각 split 그룹 중복 0을 확인했다.
고정 설정과 실행 snapshot의 해시가 일치하며 원래 개발 자료는 변경하지 않았다.
약 30Hz인 실제 자료의 불필요한 anti-alias 적용은 0개다. 원본별 진단 이미지는 33개다.
새 전처리 자료의 초기 manifest 상속 정보 한계는 `output/real_sequences_clock_v1_1/PROVENANCE.md`에 명시했다.
실제 test는 이 산출물 검사에서도 읽지 않았다.
